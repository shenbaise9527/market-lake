# 行情数据 schema 约定

整个仓库（Python / Rust / C++ 三份代码）共用这一份约定。改 schema 前先改这里。

## trades（逐笔成交）

| 字段 | 类型 | 单位/精度 | 说明 |
|---|---|---|---|
| `symbol` | string | — | `600000.SH` 形式，含交易所后缀 |
| `ts` | int64 | epoch **纳秒**（UTC） | 唯一时间基准，展示层再转本地时区 |
| `seq` | int64 | 交易所序号 | 同一 `(symbol, ts)` 内的排序与去重依据 |
| `px` | float64 | 元 | 见下方"价格精度" |
| `vol` | int64 | 股/手 | **统一到股**，期货手数在元数据里标注乘数 |
| `side` | int8 | — | 1 主动买 / -1 主动卖 / 0 未知（集合竞价） |
| `channel` | int16 | — | 行情通道编号，区分 L1/L2/逐笔 |

分区键（不落列，只在路径里）：`dt=YYYY-MM-DD`、`exchange=SH|SZ|CFFEX`。

## book（五档/十档快照）

`symbol`, `ts` 同上，其余为扁平列：

```
bid_px1..bid_px5, ask_px1..ask_px5      float64
bid_vol1..bid_vol5, ask_vol5..ask_vol5  int64
```

**为什么扁平而不是 `LIST<STRUCT>`**：DuckDB / Polars 对扁平列的向量化路径最成熟，
且十档固定宽度，没有变长数组的必要。要对比就自己跑第 3 周的任务 4。

## 四个关键决定

### 1. 时间用 int64 纳秒，不用 timestamp 字符串

- 字符串时间戳：不能做 min/max 剪枝（字典序碰巧可行，但依赖格式固定），比较慢 5–10 倍
- `TIMESTAMP(ns)` 逻辑类型：语义好，但跨语言/跨引擎的时区标注容易不一致，且 Arrow 的 ns 时间戳上限约到 2262 年
- `int64` 裸纳秒：任何引擎都能零成本处理，比较就是整数比较

**约定**：落地一律 `int64 ns`；对外 API 再转 `datetime64[ns]` 或 RFC3339 字符串。

### 2. 价格精度

| 场景 | 选择 | 理由 |
|---|---|---|
| 研究/回测 | `float64`（元） | 计算方便，误差在 1e-12 量级，对收益无影响 |
| 对账/清算 | `int64` 定点（×10000） | 精确相等比较；累加无误差 |

**不要**用 `decimal128` 存整列——它比 int64 慢，且压缩率更差（除非真的需要 >15 位有效数字）。

### 3. 去重键

`(exchange, symbol, ts, seq, channel)`

只用 `(symbol, ts)` 不够：同一纳秒可能有多笔成交（交易所时间戳精度有限），
必须靠 `seq` 区分。只用 `seq` 也不够：跨交易日的 seq 会重置。

### 4. Schema 演进

Parquet 支持加列（老文件读出来是 null），不支持改类型、不支持删列后重命名。

规则：
- 加列：直接加，读侧容忍 null
- 改类型：新增一列 + 回填 + 双写一个版本周期
- 删列：保留但停止写入，不要物理删除（否则老文件的列索引会错位）
- 每次变更在 `_manifest/schema_history.md` 记一笔：版本号、时间、变更内容、回填范围

## 命名与单位约定

- 字段名全小写下划线，不用驼峰（跨语言贴 schema 时少踩坑）
- 金额一律"元"，不要混"分"；成交量一律"股"，不要混"手"
- 乘数、最小变动价位、涨跌停价这些**合约级元数据**不要塞进 tick 表（会重复上亿次），
  单独一张 `instruments` 表，用 `symbol + 生效区间` 做时间维表

## 一个反例

```python
# 别这样：把合约元数据摊进每一行
{"symbol": "600000.SH", "tick_size": 0.01, "multiplier": 1, "px": 10.5, ...}
# 1 亿行 = 1 亿次重复的常量，压缩后仍占空间，且改一次要重写所有历史

# 应该这样：单独维表，join 时用 ASOF（按生效时间对齐）
instruments: (symbol, effective_from, effective_to, tick_size, multiplier, lot_size)
```
