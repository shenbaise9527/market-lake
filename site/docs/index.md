# 行情数据湖 · 学习手册

面向**海量行情数据**的本地学习手册：Parquet / Arrow / DuckDB / Polars，三语言（Python / Rust / C++）落地。
配套代码仓：`E:\work\learning\market-lake`。所有数字都是本机实测，出处逐条挂脚注。

## 这个站解决什么问题

网上关于 Parquet 的文章，八成在重复同一句"列存压缩率高、查询快"，但你真正需要知道的是：

- 为什么我的 `ts` 列占了文件 61%？
- 行组设 65,536 还是 1,048,576？依据是什么？
- 什么时候 `BYTE_STREAM_SPLIT` 反而让文件变大？
- `ASOF JOIN` 什么时候会退化成嵌套循环、跑几分钟？

**这些问题的答案不在博客里，在你自己的数字里。** 所以本站的每一章都按同一结构写：先给结论，再拆机制，然后是可跑代码和本机实测数字，最后是出处。看懂机制、跑出数字、写下结论——三步都做完才算学完一章。

## 怎么读

!!! tip "推荐顺序：结论 → 图解 → 跑代码 → 回来啃机制"
    第一遍不要试图读懂所有细节。先看 §1 结论和 §2.1 的图，把实验跑了，有了数字再回头读机制部分。
    纯文字读 Parquet 的行组布局，只会记住名词；跑一遍 `inspect` 再看同一段话，才会"啊"一声。

每章的固定七段结构，看到哪一段就知道自己进度如何：

| 段 | 内容 | 用法 |
|---|---|---|
| ① 本章结论 | 三句话 | 读完先自测能不能复述，不能就重读 |
| ② 直觉图解 | SVG 图 + 类比 | 建立正确的心智模型，替代大段文字 |
| ③ 机制拆解 | 到字节/结构体层 | 慢读，配合规范原文核对 |
| ④ 可跑代码 | 指向仓库真实文件 | 必须跑，不许只看 |
| ⑤ 实测数字 | 带版本和日期 | 和你自己的数字对比，差得多就查原因 |
| ⑥ 踩坑 | 默认值陷阱与误读 | 这一节最省时间，别跳过 |
| ⑦ 出处 | 脚注 + 页码 | 有疑问时回原文，别信二手解读 |
